# Mindrest ライセンス販売のしくみ — 設置手順

決済（Stripe）と、コードの発行・確認（Google Apps Script）をつなぐ手順です。
上から順にやれば終わります。所要はだいたい1時間です。

---

## 全体の流れ

```
お客さん                Stripe                  GAS                    アプリ
  │                      │                      │                      │
  ├─ LINEのリンクを押す ─→│                      │                      │
  │                      │                      │                      │
  ├─ カード / PayPay で払う                      │                      │
  │                      │                      │                      │
  │                      ├─ 決済ページへ戻す ──→│                      │
  │                      │   ?session_id=cs_xxx │                      │
  │                      │                      ├─ 本当に払われたか    │
  │                      │←─ 問い合わせ ────────┤   Stripeに確認       │
  │                      ├─ paid ──────────────→│                      │
  │                      │                      ├─ コードを発行        │
  │←─ 画面にコードを表示 ─────────────────────────┤   シートに記録       │
  │←─ 同じ内容をメールでも ───────────────────────┤   メール送信         │
  │                      │                      │                      │
  ├─ アプリを開いてコードを入力 ───────────────────────────────────────→│
  │                      │                      │←─ このコードは有効？ ─┤
  │                      │                      ├─ OK ────────────────→│
  │←─ 使えるようになる ────────────────────────────────────────────────┤
  │                      │                      │      （以後はオフラインでも起動）
```

## 手順1. スプレッドシートとGASを作る

1. Googleドライブで**新しいスプレッドシート**を作る。名前は `Mindrest ライセンス台帳` など
2. メニューの **拡張機能 → Apps Script** を開く
3. 出てきたエディタの中身をすべて消して、`license.gs` の中身を丸ごと貼り付ける
4. プロジェクト名を `Mindrest License` などに変えて保存

> **既存のランキング用GASには足さないでください。**
> ランキングは誰でも叩ける公開エンドポイントです。そこにStripeの鍵を置くと、
> 万一ランキング側に問題があったときに決済まわりまで巻き添えになります。分けておくのが安全です。

---

## 手順2. Stripe の制限付きキーを作る

Stripe管理画面 → **開発者 → APIキー → 制限付きキーを作成**

- 名前：`Mindrest License (read only)`
- 権限：**Checkout セッション（Checkout Sessions）を「読み取り」のみ**
- それ以外はすべて「なし」のまま

> 既存の塾のサブスクで使っているキーは**絶対に流用しないでください。**
> このキーは万一漏れても「決済が成立したか読むだけ」しかできません。
> 返金も、顧客情報の閲覧も、課金もできない状態にしておきます。

作成すると `rk_live_...` で始まる文字列が**一度だけ**表示されます。閉じると二度と見られないので、その場でコピーしてください。

---

## 手順3. キーをGASに登録する【これは平山さんの手でお願いします】

Apps Scriptエディタで、左の歯車 **プロジェクトの設定** → 下の **スクリプト プロパティ** → **プロパティを追加**

| プロパティ | 値 |
|---|---|
| `STRIPE_KEY` | 手順2でコピーした `rk_live_...` |

**保存**を押す。

> ここだけは私（Claude）が代わりに入力できません。
> APIキーやパスワードの類を入力欄に打ち込むことは、私の側で禁止されている操作です。
> 万一の取り違えや流出を防ぐための決まりなので、ここはご本人の手でお願いします。
> 貼り付けたあと、キーを画面やチャットに貼らないでください。私が知る必要はありません。

## 手順4. setup() を実行する

エディタ上部の関数名の欄で **`setup`** を選び、**実行**を押す。

- 初回は「承認が必要です」と出ます。ご自分のGoogleアカウントで許可してください
- 「このアプリはGoogleで確認されていません」と警告が出たら、**詳細 → 安全でないページに移動** で進みます（自分で書いたスクリプトなので問題ありません）
- 実行ログに「セットアップが終わりました」と出れば成功。スプレッドシートに `licenses` `devices` `log` の3つのシートができています

ログに `STRIPE_KEY は設定済みです` と出ているかも確認してください。

## 手順5. ウェブアプリとしてデプロイする

右上の **デプロイ → 新しいデプロイ**

| 項目 | 設定 |
|---|---|
| 種類 | ウェブアプリ |
| 説明 | `v1` |
| 次のユーザーとして実行 | **自分** |
| アクセスできるユーザー | **全員** |

デプロイすると `https://script.google.com/macros/s/AKfy.../exec` というURLが出ます。**これを控えてください。**以下 `【GAS_URL】` と書きます。

動作確認：ブラウザで `【GAS_URL】?action=ping` を開いて `{"ok":true}` と出ればOKです。

> **以後コードを直したときは、「デプロイを管理」→ 鉛筆マーク → バージョンを「新バージョン」にして更新**してください。
> 「新しいデプロイ」を選ぶとURLが変わってしまい、アプリ側の設定もやり直しになります。

## 手順6. Stripe の Payment Link 【テストモードは作成済み】

テストモードでは、次の状態まで作ってあります。

**商品**

| 項目 | 設定した値 |
|---|---|
| 商品名 | `Mindrest ライセンス（買い切り）` |
| 説明 | 買い切り・月額なし・アップデートは追加料金なし（「ずっと」「永久」は使っていません） |
| 料金 | **1,980円 / 一回限り** |
| 価格に税金を含める | **はい（内税）** → お客さまの支払額はちょうど 1,980円 |

**テスト用の決済リンク**

```
https://buy.stripe.com/test_4gMdR9be87t62gI88J9EI01
```

**設定した内容**

- 支払い方法：**PayPay** と **カード**（PayPay が最上段に出ます）
- メールアドレスの収集：Stripe Checkout が常に収集します（設定は不要でした）
- 請求先住所・氏名・電話番号の収集：**OFF**（不要な個人情報は集めない）
- **税金の自動徴収：OFF** — 内税1,980円をそのまま請求するためです。Stripe Tax を使うと取引ごとに追加手数料がかかり、表示価格ともズレます。※消費税の扱いは税理士に確認してください
- 支払い後：**確認ページを表示しない → 自社サイトにリダイレクト**。URLは現在プレースホルダのままです：

```
https://script.google.com/macros/s/REPLACE_WITH_GAS_DEPLOYMENT_ID/exec?action=success&session_id={CHECKOUT_SESSION_ID}
```

> **手順5でGASのURLが出たら、`REPLACE_WITH_GAS_DEPLOYMENT_ID` の部分だけ差し替えてください。**
> `{CHECKOUT_SESSION_ID}` は**この文字のまま**にしておくこと。Stripeが自動で実際のIDに置き換えます。

### 当初の想定と違った点（3つ）

**1. PayPay は本番では別途申請が必要です**

テストモードでは有効にできましたが、Stripe のダイアログにこう明記されていました。

> test mode で PayPay を有効にしても、PayPay の本番決済は有効になりません。

本番で使うには、Stripe のサポートページから**本番環境の有効化プロセス**を通す必要があります。
日数がかかる可能性があるので、**販売日を決める前に着手してください。**
間に合わなければ、カードだけで始めても販売は成立します。

なお PayPay の仕様は、今回の設計と相性がよいことを確認できました。

- **支払いの確定：即時** → 「決済したらすぐコードが出る」しくみが成立します
- **返金サポート：あり** → 14日返金保証を実行できます
- 取引額：50円〜100万円

**2.「利用規約への同意チェック」は、いまは設定できません**

Payment Link の詳細設定にこの項目はありますが、**選べない状態（グレーアウト）**でした。
Stripe の公開ビジネス情報に利用規約のURLが登録されていないためです。

利用規約を公開したあと Stripe の設定にURLを登録すれば、選べるようになります。

**3. コンビニ払いは入れていません**

入金確認までタイムラグがあり、「決済したらすぐコードが出る」しくみが成り立たないためです。

## 手順7. アプリ側にゲートを付ける【別の部屋の作業】

`license-gate.js` を `meditation/` に置き、`index.html` の `<body>` のいちばん最初に：

```html
<script src="license-gate.js"></script>
```

`license-gate.js` の冒頭 `LICENSE_URL` を `【GAS_URL】` に差し替えます。

**この作業のときに必ず伝えること：**
- 記録（`med.log.v1` など）には一切触れない実装になっています。ゲートは画面にかぶせるだけです
- ゲートを入れる更新を配信する**前に**、受講生へ塾生コードを配ってください。順番を逆にすると、朝アプリを開いた生徒が全員締め出されます

---

## 手順8. テストモードで通しで確認する【いちばん大事】

テスト用のPayment Linkは**作成済み**です（手順6）。テストキー（`rk_test_...`）でGASのプロパティを一時的に差し替えたうえで、下のリンクから次を通しで確認します。

```
https://buy.stripe.com/test_4gMdR9be87t62gI88J9EI01
```

このリンクのリダイレクト先も、テスト用GASのURLに差し替えておいてください。

- [ ] テストカード `4242 4242 4242 4242`（有効期限は未来の日付、CVCは任意の3桁）で決済できる
- [ ] 決済後にコードの画面が出る
- [ ] メールが届く
- [ ] **その画面をもう一度読み込んでも、同じコードが出る**（二重発行されない）
- [ ] アプリにそのコードを入れると使えるようになる
- [ ] アプリを再読み込みしても、もうコードを聞かれない
- [ ] 機内モードにしてもアプリが普通に開く（オフラインで使えること）
- [ ] でたらめなコードを入れると、ちゃんと断られる
- [ ] `revokeCode` でそのコードを止め、30日後の再確認でロックされる（`med.lic.v1` の `at` を古い値に書き換えれば試せます）

確認が終わったら、GASのプロパティを本番キー（`rk_live_...`）に戻し、本番のPayment Linkを使ってください。

**本番モードで自分でも1回だけ実際に買ってみることを強くすすめます。**
1,980円はStripeの手数料を引かれて戻ってくるだけで、確実さのほうが何倍も価値があります。

## 手順9. 塾生コードを配る

エディタで `issueJukuCodes` を開き、`count` を人数に、`note` を `塾生特典 2026` などに変えて実行します。
実行ログにコードが並んで出るので、それを配ってください。

- **数十人まで** → 1人1コード。流出したらその1件だけ止められます
- **100人超** → 共通コードを1つ（`count = 1`）にして全員に配り、年度で切り替えるほうが運用が楽です

## 運用でときどきやること

| やりたいこと | 実行する関数 |
|---|---|
| 売れた数を見る | `showStats` |
| 流出しているコードを探す | `findSuspiciousCodes`（登録端末数が多い順に出ます） |
| コードを止める | `revokeCode`（`target` を止めたいコードに書き換えて実行） |

`findSuspiciousCodes` で1つのコードが上限の5台に張り付いていたら、共有されている可能性があります。
ただし**すぐ止めないでください。**家族で使っているだけかもしれません。
まずそのコードのメールアドレスに連絡して、事情を聞いてからにしてください。

## 知っておいてほしい限界

正直に書いておきます。

1. **技術のわかる人にはコードを外されます。**アプリのJavaScriptは誰でも読めるので、その気になれば突破できます。これはWebアプリである限り避けられません。狙いは「泥棒を止める鍵」ではなく「URLが友達に転送されるのを止める表札」です
2. **GASからのメールは1日100通が上限**です。初日に100件を超えると翌日にずれます。画面表示とメールの二重にしてあるので実害は出にくいですが、頭には入れておいてください
3. **GASのシートが数千行になると確認が遅くなります。**数千件売れる規模になったら作り直しが必要です（そのときは嬉しい悲鳴です）
