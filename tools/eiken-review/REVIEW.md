# 英検アプリ 単語・熟語データの見直し（見直し担当への共通ルール）

あなたは英語教師（英語は母語話者レベル、日本語で日本の小中高生に教えられる）として、英検の単語・熟語アプリのデータを1件ずつ点検する。

## はじめに読むもの
- その級のデータの書き方のルール：`<アプリ>/data/INSTRUCTIONS.md`（例 `eiken-3/data/INSTRUCTIONS.md`）。
  対象の学年、例文の語数、使ってよい文法（5級・4級は時制などの制限あり）、tip の字数、d の決まりは級ごとにちがう。**ルールはその級の INSTRUCTIONS.md に従う。**
- 担当ファイル：`<アプリ>/data/review/src/w0.jsonl` など（1行1件。n はアプリの並び順の番号）。

## 見ること（本当のまちがい・生徒が誤解するものだけ。好みの言いかえはしない）
1. **m（テストの正解になる訳）**：意味がまちがい／その級で問われる中心の意味からずれている／品詞と合わない／ほかの語の m と同じで4択で区別できない。4択と「書いて答える」の正解になるので、いちばん大事。
2. **ex（英語の例文）**：
   - **見出し語が m とちがう意味（s の意味）で使われていないか。** 前回いちばん多かったまちがい（例：m「〜を溶かす」なのに例文は「解散する」の意味）。
   - 文法ミス、不自然な英語、語の使い方（コロケーション・語法）のまちがい。
   - [ ] の位置が見出し語（熟語）からずれていないか。
   - その級より難しい語・文法を使っていないか（INSTRUCTIONS.md の決まり）。
   - ほかの見出し語と例文がほぼ同じで、穴埋めの答えが2つになっていないか。
3. **ft（日本語訳）**：誤訳、不自然な日本語、[ ] が見出し語の訳の部分をちょうど囲んでいるか（1か所だけ・余分な語まで囲まない・一部だけでもない）。
4. **tip（覚え方）**：事実のまちがい。**特に語源**（もっともらしい作り話が多い。例：paramount＝para＋mount、redeem＝re＋deem、testify＝test は誤り）、存在しない言い方、まちがった派生語・語法、発音の説明の誤り（例：mourn と morning は同じ発音 → 正しくは mourning）、区別の説明の誤り。
5. **ph・p・s・d**：発音記号の明らかなまちがい（強勢の位置など）、p と s の品詞が合わない、d の品詞と訳が合わない。
6. **生徒向けとしてふさわしくない語・例文**（性的な意味でよく使われる派生語、暴力の描写が強い例文など）は外すか言いかえる。
7. 見出し語 w はどちらも直さない（熟語の表記もそのまま）。

## 直さないもの
- 意味の範囲に入っている言いかえ、文体の好み、すでに自然な文の書きかえ。
- 語源がはっきりしないが「覚えるための絵」として書いているもの（明らかな作り話でなければ残す）。

## 出力
担当ファイルを全件読み、直す必要があるものだけを `<アプリ>/data/review/w0.jsonl`（担当と同じ名前。src/ の外）に JSON Lines で書く。直すところがない件は書かない。0件なら空のファイルを作る。

```
{"n":番号,"w":"見出し語","fix":{"m":"新しい値","ex":"…","ft":"…"},"why":"何がまちがいか（日本語で短く）"}
```
- fix には直す項目だけ入れる。s・d は配列ごと書く。ex を直したら ft も合わせる。
- 直した値も INSTRUCTIONS.md の決まり（m の字数、ex の語数と [ ]、ft の [ ] は1か所、tip の字数、d の訳の字数）を守る。
- 書き終えたら python3 で、全行 json.loads できるか、n と w が担当ファイルと合っているかを確かめる。
- 担当ファイル（src/）と words.js・idioms.js は書きかえない。作業用のスクリプトを作るなら scratchpad に担当名を頭につけた名前で（ほかの担当とぶつからないように）。
- 最後に、点検した件数・直した件数・主なまちがいの種類・直さなかったが気になった点を短く報告する。
